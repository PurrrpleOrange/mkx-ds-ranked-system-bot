# Discord-команды

## `/ranked`

Команда работает с текущим `ACTIVE` сезоном. Если активного сезона нет, бот возвращает ошибку и не открывает регистрацию или меню.

### Регистрация

Для Discord-пользователя без участия в активном сезоне `/ranked` открывает modal игрового ника. Ник обрезается по краям, должен содержать 2–32 символа и быть уникальным внутри сезона без учёта регистра.

При первой регистрации создаётся постоянный `Player` и сезонный `SeasonPlayer`. В следующем сезоне существующий `Player` используется повторно, его Discord username обновляется, а новое участие создаётся с MMR 1000 и нулём игр. Регистрация требуется заново в каждом сезоне.

### Профиль и изменение имени

Зарегистрированному участнику `/ranked` показывает ephemeral-карточку: сезон, display name, MMR, место, tier, число игр и даты. До первого матча место отсутствует, tier — «Без ранга».

Кнопка «Изменить профиль» меняет только `season_players.display_name` активного сезона. Рейтинг, игры, матчи и имя в завершённых сезонах не изменяются.

Исключённому игроку `/ranked` показывает уведомление «Вы были удалены из текущего сезона пользователем <@Discord ID администратора>», дату удаления, сезон, сохранённые MMR и число игр. Доступны кнопки истории матчей и рейтинга. Внесение и подтверждение результатов, изменение профиля и повторная регистрация в этом сезоне запрещены, в том числе через старые кнопки и формы. В следующем сезоне можно зарегистрироваться заново.

### Leaderboard

«Топ игроков» выводит весь leaderboard активного сезона. Участники без матчей не включаются. Порядок:

1. `rating` по убыванию;
2. `gamesPlayed` по убыванию;
3. внутренний `player.id` по возрастанию.

Вывод содержит место, сезонный ник, Discord username, MMR и число игр и группируется по tier. Длинный список разбивается на несколько ephemeral-сообщений; UI-пагинации нет.

### История матчей

«История матчей» предлагает два варианта:

- «Моя история» использует Discord ID нажавшего пользователя;
- «История игрока» открывает Discord User Select и показывает историю выбранного пользователя.

В обоих случаях пользователь должен существовать и быть зарегистрирован в активном сезоне. Показывается вся история текущего сезона в обратном хронологическом порядке: match ID, WIN/LOSE, соперник, счёт, rating delta и дата. Длинный вывод разбивается по лимиту Discord без кнопок страниц. Просмотр чужой истории не ограничен владельцем профиля или администратором.

### Заявление матча

1. Репортер нажимает «Внести результат».
2. Через Discord User Select выбирает соперника.
3. В modal вводит собственный счёт и счёт соперника.
4. Сервис проверяет, что это разные положительные Discord IDs, оба участника зарегистрированы в активном сезоне и ровно один счёт равен 5, а второй находится в диапазоне 0–4.
5. Бот публикует в канале сообщение с заявленным результатом и упоминанием соперника.

Репортер может указать как свою победу, так и своё поражение. Победитель определяется по введённому счёту, а не по тому, кто отправил форму.

### Подтверждение и отклонение

- «Подтвердить» может только пользователь, выбранный как соперник. После подтверждения матч записывается, оба рейтинга и `gamesPlayed` обновляются, а публичное сообщение заменяется итогом без кнопок.
- «Отклонить» может репортер или выбранный соперник. База не изменяется; сообщение заменяется уведомлением об отмене без кнопок.
- Любой третий пользователь получает ephemeral-отказ.

В одном запущенном экземпляре повторная обработка одного confirmation message защищена in-memory guard по message ID. Это не постоянный challenge record: после рестарта или между несколькими экземплярами защита не сохраняется, а разные сообщения с одинаковым результатом не дедуплицируются.

## `/admin`

### Права

Команда регистрируется с default permission `ADMINISTRATOR`. Кроме этого, `AdminCommandListener` перед каждой командой, кнопкой, modal и user-select проверяет, что interaction пришёл из guild, `Member` доступен и имеет Discord permission `ADMINISTRATOR`. Неадминистративный вызов не достигает сервисного слоя.

Корневая панель и служебные ответы ephemeral. Публикация leaderboard, объявление об активации и объявление о завершении сезона публичны.

### Публикация leaderboard

«Опубликовать рейтинг» отправляет в текущий канал полный нумерованный список активного сезона: сезонный ник, MMR и число игр. Участники без матчей не попадают в публикацию. Длинный результат делится на сообщения.

### Управление сезонами

Доступные операции:

- вывести все сезоны с internal ID, номером, статусом и названием;
- создать `CREATED` сезон с заданными администратором положительным уникальным номером, названием и необязательной плановой датой;
- активировать выбранный по номеру `CREATED` сезон, установить `startDate` и опубликовать объявление;
- изменить номер, название и необязательную плановую дату текущего `ACTIVE` сезона одной транзакцией;
- завершить активный сезон, установить `endDate`, сохранить места игроков с матчами и опубликовать объявление;
- получить по ID или номеру статистику `FINISHED` сезона: число зарегистрированных игроков, число матчей, средний рейтинг ranked-участников и топ-10.

Одновременно активен максимум один сезон. Регистрация и матчи невозможны без `ACTIVE` сезона.

### Управление матчами

Актуальная видимая панель содержит одну операцию: «Удалить матч». Администратор вводит match ID из истории игрока. Для матча активного сезона сервис блокирует запись и участников, вычитает сохранённые delta, уменьшает `gamesPlayed` и удаляет матч в одной транзакции.

Матчи завершённых или неактивных сезонов откатывать нельзя. Повторное удаление невозможно. Rollback не пересчитывает последующие Elo-изменения: он арифметически отменяет delta выбранной записи, даже если после неё были другие матчи.

В listener существуют compatibility-handler’ы просмотра матча по ID, но актуальное меню не создаёт соответствующую кнопку; поэтому эта операция не считается доступной через текущую панель.

### Управление игроками

- «Вывести всех зарегистрированных игроков» показывает всех неисключённых участников активного сезона, включая `gamesPlayed = 0`;
- «Посмотреть статистику игрока» использует Discord User Select и показывает сезонный профиль выбранного пользователя.
- «Удалить игрока из сезона» открывает выбор пользователя и подтверждение с ником и сезоном. Подтверждение исключает игрока только из указанного активного сезона; отмена ничего не меняет. Повторное удаление или подтверждение после смены сезона отклоняется.
- «Вернуть игрока в сезон» открывает выбор удалённого пользователя и подтверждение с его сохранёнными MMR и числом игр. После подтверждения игрок возвращается в список участников и рейтинг (если есть матчи), а `/ranked` снова показывает обычное меню с внесением результатов и редактированием профиля. Ник, рейтинг, число игр, история матчей и очки соперников не меняются. Восстановление возможно только в том активном сезоне, из которого игрок был исключён. Повторное восстановление, выбор действующего или незарегистрированного участника и подтверждение после смены сезона отклоняются.

Исключение сохраняет участие в БД, матчи, рейтинг и число игр всех соперников. Игрок исчезает из списка участников, leaderboard и итоговых мест, но сохраняет доступ к статистике; администратор также может просмотреть его профиль с отметкой об исключении. Число участников в статистике сезона не включает исключённых, число матчей включает сохранённые матчи с ними. Их сезонные ники остаются занятыми для сохранения истории. Отдельное действие «Удалить матч» по-прежнему откатывает очки выбранного матча, включая матч с исключённым игроком.

Reset и ручное изменение рейтинга игрока в панели отсутствуют.
