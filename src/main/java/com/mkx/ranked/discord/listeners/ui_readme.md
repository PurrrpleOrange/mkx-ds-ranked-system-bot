# 🗺️ Карта интерфейса MKX Ranked Bot

Пользовательский интерфейс начинается с `/ranked`, а административный — с `/admin`.
`/ranked` запускает одну из двух веток: **Регистрация** или **Главное меню**.

## 1. Ветка Регистрации (Новый игрок)

Если игрок не зарегистрирован в текущем ACTIVE сезоне, бот отправляет модальное окно. После отправки формы участие создаётся сразу; отдельного confirmation flow регистрации нет.

| ID Компонента | Тип | Текст / Описание | Что делает в коде |
| :--- | :--- | :--- | :--- |
| `modal:register_user` | Modal (Форма) | *Ввод игрового никнейма* | Открывается при `/ranked`, если пользователь ещё не зарегистрирован в активном сезоне. Создаёт сезонное участие напрямую. |

---

## 2. Ветка Главного Меню (Зарегистрированный игрок)

Если игрок есть в БД, команда `/ranked` выдает ему красивую Embed-карточку профиля и три основные кнопки навигации.

| ID Компонента | Тип | Текст / Описание | Что делает в коде |
| :--- | :--- | :--- | :--- |
| `btn:report_match` | Button (Primary) | **📝 Внести результат** | Запускает первый шаг внесения матча (выдает выпадающий список `EntitySelectMenu`). |
| `btn:match_history` | Button (Secondary)| **📜 История матчей** | Открывает первую страницу (Page 0) истории матчей. |
| `btn:leaderboard` | Button (Secondary)| **📊 Топ игроков** | Выводит Топ-10 игроков ладдера. |

---

## 3. Флоу внесения результатов (Двухшаговая система)

Это самая сложная цепочка, которую мы переделали, чтобы избавиться от костылей с вводом никнеймов вручную. Запускается по кнопке `btn:report_match`.

| ID Компонента | Тип | Текст / Описание | Что делает в коде |
| :--- | :--- | :--- | :--- |
| `select:opponent_report` | EntitySelectMenu | *Выбор пользователя* | Родной список Discord. Игрок кликает и выбирает оппонента. При выборе генерируется модалка ниже. |
| `modal:report_match:{id}`| Modal (Форма) | *Ввод счета (0-5)* | **ID динамический!** В него уже вшит Discord ID оппонента. Внутри формы игрок вписывает только счет. |

---

## 4. Флоу подтверждения матча (Для соперника)

Когда игрок заполнил модалку со счетом, бот отправляет публичное сообщение в канал, пингует оппонента и ждет его реакции. Эти кнопки ловит `MatchConfirmationListener`.

| ID Компонента | Тип | Текст / Описание | Что делает в коде |
| :--- | :--- | :--- | :--- |
| `confirm_match:{r}:{o}:{ms}:{os}`| Button (Success) | **✅ Подтвердить** | **ID динамический!** Хранит ID репортера, оппонента и оба счета. Нажать может *только оппонент*. Записывает матч в БД. |
| `reject_match:{r}:{o}` | Button (Danger) | **❌ Отклонить** | Нажать может оппонент (или репортер). Отменяет запись матча и стирает сообщение. |

---

## 5. Пагинация (История матчей)

Запускается по кнопке `btn:match_history`. Эти кнопки перерисовывают сообщение, подгружая новые матчи из базы.

| ID Компонента | Тип | Текст / Описание | Что делает в коде |
| :--- | :--- | :--- | :--- |
| `btn:history_page:{page}`| Button (Primary) | **◀️ Назад** / **Вперед ▶️** | **ID динамический!** Вшита страница, на которую нужно перейти. Вызывает метод `handleMatchHistoryPage` с флагом `isUpdate = true`. |
| `btn:noop` | Button (Secondary)| **[ 1 / 5 ]** (Неактивна) | Пустышка. Просто визуальный индикатор текущей страницы между кнопками «Назад» и «Вперед». |

## 6. Пагинация таблицы лидеров

Таблица загружается из `LeaderboardService` по 10 игроков. Номер страницы хранится только в ID кнопки;
устаревшая страница автоматически переводится на последнюю доступную.

| ID Компонента | Тип | Текст / Описание | Что делает в коде |
| :--- | :--- | :--- | :--- |
| `btn:leaderboard_page:{page}` | Button (Primary) | **Назад** / **Вперед** | Загружает указанную страницу таблицы лидеров. |
| `btn:noop` | Button (Secondary) | **[ 1 / 5 ]** (Неактивна) | Показывает текущую страницу. |

---

## 7. Административная команда `/admin`

Команда регистрируется с default permission `ADMINISTRATOR`. `AdminCommandListener` дополнительно проверяет, что interaction пришёл из guild, `Member` доступен и имеет `Permission.ADMINISTRATOR`, до любого вызова service layer. Все ответы ephemeral, кроме явной публикации полного рейтинга.

| Команда | Параметры | Что делает |
| :--- | :--- | :--- |
| `/admin season create` | `name` (обязательный), `planned_end` (ISO date-time, необязательный) | Создаёт сезон в статусе CREATED. |
| `/admin season activate` | `number` | Активирует CREATED сезон через lifecycle `SeasonService`. |
| `/admin season finish` | — | Завершает ACTIVE сезон через `finishActiveSeason()`, сохраняя finalRank. |
| `/admin season info` | `number` (необязательный) | Показывает указанный сезон или текущий ACTIVE. |
| `/admin match info` | `id` | Показывает admin DTO матча. |
| `/admin match delete` | `id` | Вызывает `MatchService.revertMatch()`: откатывает delta/gamesPlayed и удаляет матч. |
| `/admin player info` | `user` | Показывает профиль Discord-пользователя в ACTIVE сезоне. |
| `/admin leaderboard publish` | — | Публично отправляет полный рейтинг в текущий канал. |

`player reset` намеренно отсутствует: изменение rating/gamesPlayed при сохранённой истории матчей нарушило бы инварианты данных. Legacy-кнопка `btn:admin_send_rating` удалена; её функция перенесена в `/admin leaderboard publish`.

## 💡 Как работают Листенеры (Кто за что отвечает)

Чтобы ничего не путать, запомни простое распределение ролей:

1. **`RankedCommandListener`**: Твой главный диспетчер. Отвечает за вызов `/ranked`, форму регистрации, все кнопки главного меню, кнопки пагинации истории и выпадающий список выбора оппонента.
2. **`ModalInteractionListener`**: Отвечает за форму внесения счета матча (`modal:report_match:*`). Регистрационный modal (`modal:register_user`) обрабатывается в `RankedCommandListener`.
3. **`MatchConfirmationListener`**: Служба безопасности. Ловит **только** публичные кнопки `confirm_match` и `reject_match`, проверяя, тот ли человек на них нажал.
4. **`AdminCommandListener`**: Обрабатывает только `/admin`, проверяет guild/admin permissions и делегирует операции в `AdminService`.
