# 🗺️ Карта интерфейса MKX Ranked Bot

Пользовательский интерфейс начинается с `/ranked`, а административный — с `/admin`.
`/ranked` запускает одну из двух веток: **Регистрация** или **Главное меню**.

## 1. Ветка Регистрации (Новый игрок)

Если игрок не зарегистрирован в текущем ACTIVE сезоне, бот отправляет модальное окно. После отправки формы участие создаётся сразу; отдельного confirmation flow регистрации нет.

| ID Компонента | Тип | Текст / Описание | Что делает в коде |
| :--- | :--- | :--- | :--- |
| `modal:register_user` | Modal (Форма) | *Ввод игрового никнейма* | Открывается при `/ranked`, если пользователь ещё не зарегистрирован в активном сезоне. Создаёт сезонное участие напрямую. |

---

## 2. Ветка Главного Меню (Зарегистрированный игрок)

Если игрок есть в БД, команда `/ranked` выдает ему красивую Embed-карточку профиля и три основные кнопки навигации.

| ID Компонента | Тип | Текст / Описание | Что делает в коде |
| :--- | :--- | :--- | :--- |
| `btn:report_match` | Button (Primary) | **📝 Внести результат** | Запускает первый шаг внесения матча (выдает выпадающий список `EntitySelectMenu`). |
| `btn:match_history` | Button (Secondary)| **📜 История матчей** | Выводит всю историю текущего сезона с `match_id`, без пагинации. |
| `btn:leaderboard` | Button (Secondary)| **📊 Топ игроков** | Выводит полный рейтинг текущего сезона без пагинации. |

---

## 3. Флоу внесения результатов (Двухшаговая система)

Это самая сложная цепочка, которую мы переделали, чтобы избавиться от костылей с вводом никнеймов вручную. Запускается по кнопке `btn:report_match`.

| ID Компонента | Тип | Текст / Описание | Что делает в коде |
| :--- | :--- | :--- | :--- |
| `select:opponent_report` | EntitySelectMenu | *Выбор пользователя* | Родной список Discord. Игрок кликает и выбирает оппонента. При выборе генерируется модалка ниже. |
| `modal:report_match:{id}`| Modal (Форма) | *Ввод счета (0-5)* | **ID динамический!** В него уже вшит Discord ID оппонента. Внутри формы игрок вписывает только счет. |

---

## 4. Флоу подтверждения матча (Для соперника)

Когда игрок заполнил модалку со счетом, бот отправляет публичное сообщение в канал, пингует оппонента и ждет его реакции. Эти кнопки ловит `MatchConfirmationListener`.

| ID Компонента | Тип | Текст / Описание | Что делает в коде |
| :--- | :--- | :--- | :--- |
| `confirm_match:{r}:{o}:{ms}:{os}`| Button (Success) | **✅ Подтвердить** | **ID динамический!** Хранит ID репортера, оппонента и оба счета. Нажать может *только оппонент*. Записывает матч в БД. |
| `reject_match:{r}:{o}` | Button (Danger) | **❌ Отклонить** | Нажать может оппонент (или репортер). Отменяет запись матча и стирает сообщение. |

---

## 5. Полная история матчей

Кнопка `btn:match_history` загружает все матчи игрока в текущем сезоне одним списком без пагинации. Каждая строка содержит `match_id`, который игрок может передать администратору для кнопок «Матч» или «Удалить матч» в панели `/admin`.

Если список превышает технический лимит одного Discord-сообщения, бот отправляет несколько последовательных ephemeral-сообщений без кнопок навигации.

## 6. Полная таблица лидеров

Кнопка `btn:leaderboard` загружает весь рейтинг текущего сезона одним списком. Пагинация и кнопки «Назад/Вперёд» не используются; длинная выдача автоматически разбивается только по лимиту Discord-сообщения.

---

## 7. Административная команда `/admin`

`/admin` — единственная административная slash-команда. Она открывает корневую ephemeral embed-панель с четырьмя кнопками: публикация рейтинга, управление сезонами, управление матчами и управление игроками. Каждый раздел открывает отдельный embed с кратким гайдом и своими кнопками. Параметры операций запрашиваются через modal или Discord user-select.

Команда регистрируется с default permission `ADMINISTRATOR`. `AdminCommandListener` повторяет проверку guild, `Member` и `Permission.ADMINISTRATOR` для самой команды, каждой кнопки, modal и user-select до любого вызова service layer. Все ответы ephemeral, кроме публикации рейтинга и публичных объявлений об активации/завершении сезона.

### Корневая панель

| Component ID | Что открывает/делает |
| :--- | :--- |
| `admin:button:leaderboard_publish` | Публично отправляет полный рейтинг в текущий канал. |
| `admin:button:manage_seasons` | Открывает embed «Управление сезонами». |
| `admin:button:manage_matches` | Открывает embed «Управление матчами». |
| `admin:button:manage_players` | Открывает embed «Управление игроками». |

### Управление сезонами

| Component ID | Что делает |
| :--- | :--- |
| `admin:button:season_list` | Показывает все сезоны с internal ID, номером, статусом и названием. |
| `admin:button:season_create` | Через modal создаёт сезон в статусе CREATED. |
| `admin:button:season_activate` | Активирует CREATED сезон и публикует объявление о новом сезоне и повторной регистрации. |
| `admin:button:season_finish` | Завершает ACTIVE сезон, сохраняет finalRank и публикует объявление об окончании. |
| `admin:button:season_statistics` | Показывает статистику завершённого сезона: игроков, матчи, средний рейтинг и топ-10. |
| `admin:button:season_planned_end` | Кнопка «Изменить информацию о сезоне»: меняет плановую дату ACTIVE сезона под lifecycle write lock. |

### Управление матчами и игроками

| Component ID | Что делает |
| :--- | :--- |
| `admin:button:match_delete` | Откатывает delta/gamesPlayed и удаляет матч через `MatchService.revertMatch()`. |
| `admin:button:player_info` | Через Discord user-select показывает статистику игрока ACTIVE сезона. |

`player reset` намеренно отсутствует: изменение rating/gamesPlayed при сохранённой истории матчей нарушило бы инварианты данных. Legacy-кнопка `btn:admin_send_rating` удалена; её функция перенесена в кнопку публикации административной панели.

## 💡 Как работают Листенеры (Кто за что отвечает)

Чтобы ничего не путать, запомни простое распределение ролей:

1. **`RankedCommandListener`**: Твой главный диспетчер. Отвечает за вызов `/ranked`, форму регистрации, кнопки главного меню, полные списки истории/рейтинга и выбор оппонента.
2. **`ModalInteractionListener`**: Отвечает за форму внесения счета матча (`modal:report_match:*`). Регистрационный modal (`modal:register_user`) обрабатывается в `RankedCommandListener`.
3. **`MatchConfirmationListener`**: Служба безопасности. Ловит **только** публичные кнопки `confirm_match` и `reject_match`, проверяя, тот ли человек на них нажал.
4. **`AdminCommandListener`**: Обрабатывает `/admin` и компоненты `admin:*`, повторно проверяет guild/admin permissions и делегирует операции в `AdminService`.
